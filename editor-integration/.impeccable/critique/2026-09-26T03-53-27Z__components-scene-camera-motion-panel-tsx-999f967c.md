**先回答：到底是不是同一套底层？**

| 层面 | 当前实现 | 判断 |

**从导演制作分镜的角度看，基础能力已经相当完整，缺的是把能力组织成创作动作。**

| 改弯曲路线 | 可拖端点、路线和控制柄 | 手柄与时间轴命中区域小 |

例如“物品从左移到右，相机跟拍并逐渐拉远，最后切到侧面”，现有结构能够表达。问题在于创作者必须理解相机状态、物品轨道、路径片段和输出设置之间的关系，才能完成这件事。

还有一个应明确的产品概念：**相机是机位，镜头是时间里的一段拍摄。**目前切镜数据主要是“某一秒使用哪台相机”，尚不是带名称、备注、缩略图的完整分镜单元。可以在现有切镜数据上增加轻量镜头卡片，不必另造动画引擎。

**有三项设计值得继续保留。**

- “创建／更新关键帧”作为统一主按钮，避免用户猜测什么时候自动写入动画。
- 相机和物品在同一时间轴上协作；调整空间路线与调整时间原则上分开。
- 焦距、注视、跟随、对焦各司其职，并把精确数值和高级属性折叠起来。

**我建议优先处理下面五项问题。P1 表示直接妨碍核心流程，P2 表示影响效率与完整性。**

**1．[P1] 先统一“速度控制的到底是什么”，修复结果不一致。**

这不只是 UI 文案问题。我运行当前采样函数，用四秒完成移动、旋转和缩放：路径设为匀速，到第一秒位置走了 25%，旋转和缩放只完成约 12.9%。再将路径速度改为“先慢后快”，位置改变，旋转和缩放不变。

原因是路径面板只改 segment.easing，而物品旋转／缩放继续读取 point.easing。界面上还存在两种入口：物品选关键帧就能改速度，相机则要选路径段。证据见 [物品采样](/Users/xiaohai/三维系统/editor-integration/packages/viewer/src/lib/object-motion.ts:23)、[路径修改](/Users/xiaohai/三维系统/editor-integration/packages/editor/src/components/scene-camera/motion-panel.tsx:72)。

建议统一为：**选关键帧改“这一刻的状态”，选两帧之间改“怎样运动过去”。**默认让移动、转向、缩放服从同一段的时间进度；如果保留独立速度，应明确作为高级能力。0°→360° 的实测也显示中间姿态几乎没有旋转，商品自转应提供明确圈数和方向，不能只依赖起止姿态。

**2．[P1] 让动画成为独立工作区，并持续说明编辑对象、当前视角和成片镜头。**

现在物品动画要从“场景相机→视频时间轴”进入；添加切镜又要打开“输出”。这与用户的任务顺序不吻合。已在浏览器确认，入口代码见 [相机浮窗](/Users/xiaohai/三维系统/editor-integration/packages/editor/src/components/scene-camera/overlay.tsx:280)、[切镜操作](/Users/xiaohai/三维系统/editor-integration/packages/editor/src/components/scene-camera/motion-scene-controls.tsx:147)。

建议增加直接的“动画／分镜”入口。点击相机轨道仍可进入该相机画面，但把“已激活／取消激活”改成“正在通过相机 A 取景／返回场景”。保持一条清楚的状态说明，例如“编辑：运动物品｜视角：场景总览｜成片：相机 A”。切镜按钮放到成片轨道旁，输出弹层只承担输出相关设置。

“编辑选中物品动画”也应整理：系统已会在选择物品后进入物品动画状态，原有场景选择随后被清空，该按钮又变灰，容易让用户误以为没有进入成功。应采用直接选择流程，或将其改为真正的“添加物品”选择入口。

**3．[P1] 把画面空间还给构图，尤其是笔记本窗口。**

实测三条轨道时，时间线在 1600×1000 和 1280×720 下都约 330px 高；后者的右侧属性区只剩约 220px。时间线连续用了播放栏、编辑状态栏、缩放栏、轨道区和播放范围栏。容器没有明显破版，但主要创作画面被压缩了。

建议时间线支持拖动高度和紧凑模式，合并状态与缩放工具，按需展开播放范围；属性区可收起，导航提示在掌握后缩为帮助入口。初始高度应随窗口和轨道数量调整，不要让固定工具条占用压过画面。相关结构见 [motion-panel.tsx](/Users/xiaohai/三维系统/editor-integration/packages/editor/src/components/scene-camera/motion-panel.tsx:83)。

**4．[P1] 把“调整路线”变成看得见、抓得住的主要功能。**

两个菱形之间的路径编辑按钮没有文字，默认近乎透明，只有约 12px 高；时间间隔很短时，可点击宽度还会缩到零。核心卖点不能依赖用户碰巧悬停发现。见 [路径段按钮](/Users/xiaohai/三维系统/editor-integration/packages/editor/src/components/scene-camera/motion-timeline.tsx:610)。

建议选中轨道后明确显示“调整路线”，路径段保持可见，并标出选中的是 A→B。画布上的视觉点可以小，实际命中区域应扩大；补上方向键微调与可选数值输入。鼠标导航已有提示和部分时间线快捷键，应在此基础上补齐，而不是重新堆一套操作系统。

**5．[P2] 增加少量导演任务入口，补齐轻量分镜交付。**

当前预设叫“圆形、方形、画路线”，表达的是几何形状。普通用户更容易理解“向前推近、向后拉远、围绕主体、跟随主体、物品自转”。这些入口应生成现有关键帧与路径，创建后仍用同一套工具调整。

建议先补环绕主体、自转、停留和循环预览，再增加镜头名称、备注、缩略图及分镜图导出。完整骨骼编辑、复杂曲线图和非线性动画混合暂时不必成为这轮重点。

**界面应围绕一个连续流程组织：选中对象 → 调整画面或姿态 → 记录这一刻 → 移动时间 → 调整下一状态 → 记录 → 播放检查。**

| 区域 | 应承担的主要任务 |
|---|---|
| 中央画面 | 相机取景、物品摆放、直接调路线，始终占最大空间 |
| 画面附近 | 当前视角、返回场景、必要的临时操作提示 |
| 右侧上下文属性 | 相机显示焦距／注视；物品显示移动／旋转／缩放；选中片段显示路线／速度 |
| 底部时间线 | 播放、当前时间、统一记帧、相机和物品轨道 |
| 成片轨道 | 镜头区间、在此切镜、当前成片相机 |
| 输出弹层 | 画幅、分辨率、帧率、输出范围及导出选择 |

新手最容易卡在“第一帧之后做什么”；熟练用户最受制于状态切换和有限画面空间；键盘或触控板用户最受制于路径手柄。这三类问题比继续增加参数更值得先解决。

较小的改进包括：镜头焦距不必默认显示到三位小数；重要状态文字比刻度更需要可读字号；路径编辑完成应有明确反馈，避免它与待记帧的姿态草稿混淆；“平滑衔接”与“匀速／先慢后快”等速度选择应解释区别。
