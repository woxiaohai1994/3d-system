# 控件显示遮挡与原版姿态选择

本轮继续完整源码集成目标，未认定整体功能、UI 和视觉全部对应原版。

## 原版默认普通点选

默认姿态模式会收集选择矩形内每个骨骼独立的命中和最小深度，包含重叠后方骨骼。关闭 `show_in_front` 不会使用已显示场景的深度删除点选候选。14、9、5 矩形查询依据各自命中数量缩小范围，再应用已提取的骨骼优先级。显示遮挡和点选范围需要分别对应源码。

完整下载的 v4.3.0 文件由 `vendor/blender-rig-picking/UPSTREAM.json` 保存原始 URL 和 SHA-256，本轮新增五个完整文件，合计 17 个。生成器校验全部哈希。

| 源码 | 确认的行为 |
| --- | --- |
| `userdef_default.c:59`、`view3d_select.cc:2095,2208` | 默认未禁用深度拾取，普通骨骼查询强制 `VIEW3D_SELECT_PICK_ALL`，即使随后要取最近骨骼 |
| `draw_manager_c.cc:2601` | 新建选择 depth-only framebuffer 并清为 1，没有复制主场景深度 |
| `gpu_select_pick.cc:387,497,521` | 每 ID 扫描各矩形最小深度，记录后清深度，保留后方 ID |
| `DNA_scene_defaults.h:344`、`view3d_view.cc:515` | 默认开启对象模式锁，姿态模式过滤不兼容的普通对象 |
| `DNA_view3d_defaults.h:40`、`draw_manager_c.cc:2441` | Bone Selection Overlay 默认关闭；开启后的“只绘同模式骨架”不能当默认分支 |
| `draw_manager_exec.cc:222` | 前置选择 pass 将深度范围压到 `[0,0.01]`；整个同一 rig 共同缩放，类别优先级保持，量化可能产生并列 |

本结论仅限普通单击选择；框选、圆选等分支不能据此认定相同。

## 应用修改

取景移除中心射线的普通场景遮挡过滤。主图与取景框共用完整画布的原生姿态指针入口，冻结实际显示的 `sourceRigClip` 四边形，执行 GPU 14/9/5 像素查询及原版优先级。控件只负责绘制与发布四边形，不再用 CPU 射线或预筛选决定是否进入骨骼选择。异步查询期间保留移动、松手和点击归属，避免短点击落入普通场景取消选择。

显示修正使用通用 LayerPass 的主场景深度上下文，按材质 `depthTest` 对实际光栅片元深度作判断，保留原材质的线端、透明度和裁剪。材质深度开关动态读取；绘制异常也恢复原 shader context，避免渲染回退引用已经释放的 pass。

置前显示与置前选择必须分开：`overlay_armature.cc:323` 仅在 `DRW_state_is_select()` 时启用 `IN_FRONT_SELECT`；普通显示仍用 `DEPTH_LESS_EQUAL | WRITE_DEPTH`。`overlay_engine.cc:586` 为置前显示分配独立 D24_STENCIL8，`overlay_armature.cc:3302` 绘制前只清一次深度。主视口现已接入独立置前层：完整预览使用独立深度渲染目标并按预乘透明度合成，轻量预览先画场景、再单次清深度绘制全部置前控件。控件之间仍使用正常深度测试与写入，显示深度没有压缩到 `[0,0.01]`。取景器也使用独立置前深度。

## 验证与未完成项

原 C++ oracle 重新编译并生成 96 组选择、180 组裁剪、200 组鼠标位置结果。源 GLSL 线框扩展已通过 float32 WASM 移植，绘制与拾取共享实际四边形；仍未与原版 GPU 逐像素核对极近深度和并列深度，WebGPU `depth24plus` 的物理格式也依赖设备，不能宣称跨后端逐像素相同。

浏览器测试场景为 `localhost:3002/scene/4d3b26be8028`。此前“关闭置前后所有控件都应消失”的测试预期错误：部分控件实际高于地面；整体 Y=-20 的后续测试又存在控件移出可见区域的问题，不能单独作为置前验收。改为整体沿世界 Y 移动 -6，保持瞄准控件在画布内。轻量预览关闭置前时瞄准控件消失，开启时重新出现；切换完整预览后开启仍显示，关闭再次消失。位移测试结束后通过参数面板核对整体 XYZ=0，置前开关恢复开启。上述结果不等于所有半透明边缘和控件交叠测试已通过。

姿态编辑时隐藏旧相机实体，并禁用其后代的射线命中；仅设置父级不可见并不能阻止 Three 的射线命中。退出编辑或注册对象更换时恢复原可见性与 raycast。视锥和相机注册根仍保留。重新构建 nodes/viewer 并刷新浏览器后，重复拖动机位和一次撤销，旧实体及旧位置白色描边均未再出现。普通自由相机和未进入姿态编辑的相机不受此隐藏逻辑影响；它们的相机实体外观尚未证明与 Blender 逐像素相同。

姿态骨编辑期间，普通对象的复制、删除浮条也会隐藏，以免挡住机位控件并把骨操作误变成整台相机操作。浏览器确认滑轨姿态编辑时浮条消失，切到自由相机后复制和删除入口重新出现，一次撤销回滑轨后再次隐藏。普通对象及非姿态相机沿原入口保留。

此前机位旋转没有位移的案例，是观察方向与机位到瞄准点连线平行：原版默认自由旋转围绕观察轴，该轴恰好穿过机位，因此位置只有浮点误差。真实挂载 Gizmo 的对应回归验证位置保持、旋转改变、瞄准固定、仅一次历史提交；另一个不平行的相同鼠标位移案例验证实际环绕位移。没有据此修改原版旋转公式。
