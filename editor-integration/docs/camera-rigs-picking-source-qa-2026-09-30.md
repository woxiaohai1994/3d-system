# 原版控件点选与裁剪核对

本轮继续完整集成目标，未认定视觉、UI、操作功能已经全部对应原版。

## 下载及复用的源码

`vendor/blender-rig-picking/UPSTREAM.json` 固定 Blender v4.3.0 的 12 个完整源码文件、原始 URL 与 SHA-256。文件原文保留；`scripts/blender/compile-rig-picking.py` 校验哈希并提取运行分支。

- `armature_select.cc`：优先选未选中骨骼，最近选择及循环选择分支。
- `view3d_select.cc`：14、9、5 窗口像素的逐层选择矩形，保留唯一宽框命中、缩小多重命中。
- `math_geom.cc`：线段对平面裁剪。适配层先拒绝完全处于任一平面外侧的线段，再调用原函数；原函数对平行线段假定调用者已经做这项剔除。
- `wm_event_query.cc`、`WM_types.hh`、`userdef_default.c`、`DNA_userdef_types.h`：整数区内坐标的曼哈顿距离与默认运动阈值 2，乘以界面／屏幕缩放；每次选择更新前一坐标，不按时间或点击间路径判断。
- `screen_edit.cc`：跨视口时用 `(-1,-1)` 重置坐标。浏览器适配在离开画布或换画布时执行同样重置。
- `gpu_select.cc`、`gpu_select_pick.cc`：4.3 默认选择路径按深度升序输出，再运行骨骼选择；同深度没有原版次序契约，适配层稳定保留原骨登记序。
- `select_instance.hh`、`gpu_select_next.cc`：原版实验性 Overlay Next 按选择 ID 登记序输出，与默认路径不同；本轮对应默认 4.3 路径。

场景与取景共用上述选择分支。场景事件保留每个控件的各级矩形命中和真实深度；“显示在前方”的交集距离为零时，仍保留深度用于骨骼选择。取景输入把连续点击状态传给同一选择函数。

## 原生 C++ 与回归验证

`scripts/blender/verify-rig-picking.py` 编译下载的原 C++ 函数／分支，通过 ctypes 生成独立参考数据：96 组选择结果、180 组线段裁剪、200 组连续鼠标位置判断。测试逐组比较源码提取结果，裁剪采用 float32 参考的容差。

本轮最终检查：6 个文件，94 项测试通过、0 失败、3298 项断言；编辑器类型检查、相关文件 Biome、`git diff --check` 通过。测试覆盖透视／正交、WebGL／WebGPU 裁剪坐标、穿过近远裁剪面的可见线段、完全不可见线段、重叠骨优先级、默认深度顺序、跨画布重置，以及已有 G/R/S 与取景操作回归。

## 实际前台 Chrome 操作

页面：`http://localhost:3002/scene/4d3b26be8028`，相机 1，关闭时间轴，移动模式，质心中心，无物品绑定。全过程用系统鼠标／键盘操作页面。

| 相机架 | 操作及观察 | 撤销后 |
| --- | --- | --- |
| 滑轨 | 主视图直接点机位箭头，再点瞄准箭头，活动控制骨同步；取景瞄准箭头拖动后局部位移 `[2.219, 0, 1.331]` | 位移恢复 `[0,0,0]` |
| 摇臂 | 改为摇臂，取景箭头直接从机位换选瞄准；拖动后局部位移 `[1.598, 0, 0.799]` | 位移恢复 `[0,0,0]` |
| 平面 | 改为平面，主视图与取景都直接点选瞄准线框；拖动后局部位移 `[1.737, 0.85, 0.18]`，实际焦距 23.57 毫米 | 位移恢复 `[0,0,0]`，焦距恢复 24 毫米 |

相机架两次转换随后各撤销一次，恢复原滑轨。平面类型转换后最初截图仍呈上一帧控件；在更新后的截图重新定位，实际点选和拖动通过，未把过期坐标点击计为成功。

热更新后重新启用相机编辑。临时对相机偏移骨做世界 X 方向 1 米移动，局部通道显示 `[0.707,-0.642,-0.295]`，使机位圆环与偏移圆环相交。在交叉位置连续三次点击，实际活动控制骨为“机位 → 相机偏移 → 机位”。一次撤销后再次选择偏移骨，确认三个位移通道都为零。

随后点击 Chrome 的重新加载按钮，等新页面完成加载，取景再次显示原瞄准控件、24 毫米与默认机位活动骨。直接点击取景箭头，活动控制点与取景说明同步切换为瞄准；刷新后的选择接入通过。

## 尚未对应的选择与显示行为

后续完整源码追踪推翻了本节第 2–5 点对默认普通点选的判断：默认姿态模式使用每个 ID 独立清深度的 `PICK_ALL`，不按已显示场景的深度过滤骨骼。下列内容保留为本轮当时的审查记录，当前正确语义和修改证据见 [显示遮挡与姿态选择核对](camera-rigs-depth-pose-qa-2026-09-30.md)。不得再将本节末尾的“同帧可见片段拾取”作为默认姿态点选的实现要求。

以下是源码／本地渲染路径审查得到的具体差异，不能用上述测试或无遮挡操作将其关闭：

1. 主视图控件在独立 Overlay LayerPass 中绘制，没有复用主场景深度；仅切换控件材质 `depthTest` 不足以实现关闭“显示在前方”的真实遮挡。
2. 取景当前用光标中心场景射线和宽框的一份控件距离判断遮挡，不能对应 GPU 矩形逐像素可见片段。部分遮挡、多级矩形包含不同深度片段会误选或漏选。
3. 场景玻璃材质 `depthWrite:false`，实际控件可能在其后可见，CPU 射线仍把玻璃当作遮挡；透明纹理孔洞、材质裁剪也没有同帧验证。
4. 取景遮挡物的 Raycaster 没有继承相机近远裁剪，实际不绘制的近裁剪面前物体可能挡选。
5. 主视图 `event.intersections` 含后方交集；`stopPropagation` 不删除这些交集，未选中优先可能选到不可见骨骼。

下一步需要把实际材质、裁剪与场景深度生成的同帧 GPU 可见片段接入两处控件拾取，再将 14／9／5 矩形的骨骼与最小深度交给已提取的原版选择分支。优先验证部分遮挡、玻璃、透明孔洞、近裁剪面前遮挡物和重叠已选／未选骨骼。完整目标及其他尚未验证项继续有效。
