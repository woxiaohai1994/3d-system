# Add Camera Rigs 操作方式对照

核对日期：2026-09-28。来源为仓库内 Add Camera Rigs 1.9.0 原版源码（`vendor/add-camera-rigs/UPSTREAM.json` 固定提交），并在 Blender 5.2.2 LTS 当前会话中注册同一源码，实际查看 Crane 相机架、相机视图和 Camera Rig 侧栏。没有修改插件源码，也没有把会话注册说成持久安装。

## 操作对应关系

| 用途 | Blender 与原插件的方式 | 本系统的接入与取舍 |
| --- | --- | --- |
| 自由移动 | 姿态模式选控制骨后使用 Blender 的 G；轴/平面约束是可选项 | 选控制点后直接拖“自由移动”，按编辑视图的左右、上下移动；也保留 G 和数值/轴约束。写回原控制骨位移通道 |
| 围绕主体拍摄 | Camera 机位可移动，Aim 跟踪约束保持朝向；也可通过 Root 旋转移动整个架子 | “环绕瞄准点”保持 Aim 与机位距离、改变 Camera 位置。它是系统新增的交互适配，不冒充插件已有的独立环绕操作符 |
| 推近、拉远 | 移动 Camera，改变相机与 Aim 的距离 | 直接拖“推近 / 拉远”；与焦距调整分开。开启原版 Dolly Zoom 时，距离还会驱动焦距联动 |
| 整体布置 | Root 带动整套骨架 | “整体”控制点用于一起移动机位、瞄准点；相机操作使用独立交互范围，不落入模型建造的移动工具 |
| 转头与微调 | Aim 位移改变朝向；Aim 局部 Y 旋转产生倾斜；Camera_Offset 在瞄准结果上增加偏移 | 保留原控制骨、锁定通道和约束。中文入口是“瞄准”“相机偏移”，不是只改相机最终矩阵 |
| 摇臂 | Crane_Height、Crane_Arm 的局部 Y 缩放控制高度、臂长，摇臂可旋转 | 保留“支柱升降”“摇臂”及源参数。其层级运动不能用一般相机直线位移替代 |
| 轴心对齐 | Shift To Pivot 调整 Aim 与 Camera 的位置，保留两者距离 | 已有“移到轴心”对应原操作；可结合整体旋转。它和围绕当前 Aim 的直接环绕用途不同 |
| 推拉变焦与换镜头 | Dolly Zoom 让焦距随距离改变；Swap Lens 同时改变焦距与机位以维持构图 | 保留“推拉变焦”“换镜头并保持构图”；正交相机禁用这些透视镜头操作 |
| 2D 取景 | Left/Right Corner 驱动取景边界、镜头补偿；Aim 可带动两角 | 保留左右取景角、独立对焦等源控件。不能把 Dolly/Crane 的操作语义无条件套到 2D 上 |
| 查看拍到什么 | Blender 相机视图，可用独立视口并排查看；这是宿主功能 | 本次增加自动实时取景窗。编辑时直接看到当前相机画面，可移动、放大、收起；大预览仍可进入、退出 |
| 活动相机与切镜 | Make Camera Active、Add Marker and Bind | 接入系统的相机工作区、时间轴和成片输出语义；编辑取景不修改输出相机选择 |

自由移动、G/R/S、轴约束、相机视图是 Blender 提供的宿主交互。插件源码主要定义骨架、控件形状、约束、驱动与专用操作。系统需要适配这些宿主交互，不能仅复制侧栏参数，也不能绕开原骨架直接覆盖最终相机姿态。

## 本次落地

- 选中相机或进入相机工作区时自动显示实时取景。隐藏时间轴后，取景窗继续保留。
- 取景读取正在编辑的相机及未提交的姿态，切换相机时不沿用上一台的已完成状态。
- 取景与大预览共用现有渲染管线，并管理画布接管和恢复；导出仍使用独立的输出相机路由。
- 取景保持画幅比例，支持原构图辅助线、对焦拾取位置换算、加载和失败重试。
- 常规取景采用 360 分辨率档以控制编辑成本；放大窗口主要方便观察构图，不等同于最终导出质量。
- 取景窗使用左 / 中键移动机位、右键环绕瞄准点、滚轮推拉，不再显示三种模式按钮。三个动作和大世界的机位直接控件共用 `createRigDirectMotion`，并使用同一个 `rigTransformValue` 写入原 Camera 位移通道；不再把预览拖动写入 Camera_Offset。拖画面时按取景平面的相反方向移动相机，屏幕方向按各自观察视角解释。
- Dolly / Crane 保留当前瞄准强度、对象绑定、Camera_Offset 和摇臂层级。2D 同样移动 Camera，原版取景角、镜头补偿和旋转锁定继续生效；原源码没有禁止 Camera 位移，因此移除了预览自行添加的“禁环绕、改移 Root”规则。环绕是位移操作，不解锁相机旋转通道。
- 取景窗显示当前相机架类型与“机位”，开始操作时空间控件同步选中机位。自由相机使用独立姿态，正交自由相机滚轮调整可见高度。大世界观察视角仍独立，取景导航不发送主视角切换事件。
- 拖动松开确认，滚轮停止 180 毫秒后确认；Esc 取消，Shift 连续精调。一次拖动或一段连续滚动对应一次撤销。取景画面屏蔽右键菜单和默认滚动；锁定、只读、播放、大预览及失去交互所有权时不能继续操作。画幅黑边不响应相机编辑。

## 值得继续改进，但本次不冒称已经实现

1. 为“机位推拉 / 焦距 / 推拉变焦”和 Aim 倾斜增加短提示，减少用户理解原版骨架术语的负担。
2. 完善复杂场景的预览性能测量和景深质量。当前已有独立 GPU 对照，但仍有两项正交景深误差未收敛；本次取景交互通过不代表光学完全一致。

Blender 的 Lock Camera to View 和 Fly/Walk 可作为交互参考，但相机架有父级与约束，不能据此推断所有架子都能直接套用。官方扩展市场另有面向 Dolly 架的 CameraFly，这也不是 Add Camera Rigs 本身的独立飞行操作。

### 相机架与取景操作统一

- 修复前：预览拖动偏移骨、2D 平移 Root，与大世界移动 Camera 的效果不同。修复后，两端共享机位运动计算与世界坐标到控制骨局部坐标的转换，由原约束/驱动求解最终画面。
- 本轮 76 项测试、529 个断言通过，编辑器类型检查通过。覆盖三种相机架的移动、环绕、推拉，镜像/非均匀父级，空间拖动与预览求解一致，已有偏移/摇臂参数/对象绑定/瞄准强度保留，Dolly Zoom、2D 取景角驱动，模式切换，左右/中键、连续滚轮、撤销、取消和编辑/输出相机分离。
- 原生 Chrome / localhost:3002：“相机 1”、时间 0、无关键帧。滑轨预览拖动后机位控件移动、Aim 保持原位，Cmd+Z 恢复；切到摇臂后预览类型同步，拖动、滚轮推拉及撤销可用，随后撤销类型切换恢复滑轨；切到平面模式后旋转/缩放仍锁定，预览拖动只移动机位，整体、Aim 和左右取景角保持位置。
- 平面模式后续滚轮测试时工具报告用户开始操作，已停止接管。该次滚轮及最终撤销不记为实测通过，也没有继续撤销用户操作。页面留在“相机 1”的平面相机架。原生工具不能按住右键拖动，因此右键环绕通过事件测试验证，不冒称原生右键实测。

### 焦距异常保护（2026-09-28）

- 用户确认实际焦距统一为 24–85 mm。限制施加在相机架所有驱动计算之后、生成投影矩阵之前，覆盖 Dolly Zoom、2D 边界/机位驱动、镜头呼吸及旧数据。计算溢出的焦距也会得到有限值；无法确定方向的 NaN 回退到 50 mm。
- 原版源码求解器的无范围请求保留原始行为，用于 Blender 对照；系统的 `blenderRigRequest` 始终传入范围，因此空间控件、实时取景、动画采样和输出共用受限结果。原控制骨和关键帧数据不因读取而重写。
- 自由相机的旧 `verticalFov` 不再绕过焦距范围。拍摄视角和渲染共用有效视场角，景深使用实际焦距。极端广角的观察视图被保存为相机时也受此范围限制。
- 镜头面板显示实际焦距，越界时提示“已达 24–85 mm 限制”；基本焦距和换镜头输入使用同一范围。到达边界后机位仍可移动，但驱动的构图补偿不再完全保持原画幅。这是本系统明确的产品限制，不宣称越界时仍与原插件无限范围等效。
- 相机目录及相关 Viewer 回归共 595 项通过、0 失败；包括极端焦距、取景边界接近重合、极小推拉参考距离、连续推拉往返、旧视场角、原版求解对照、父级变换、撤销和关键帧。正常画幅保持测试使用范围内镜头，旧极端参数另有专门回归。
- 原生 Chrome / localhost:3002：时间轴关闭，选中“相机1”的平面相机架。实时图像完成渲染，显示实际焦距 24 mm 及限制提示；拖动机位“推近 / 拉远”后外部控件与取景变化，焦距仍为 24 mm，随后撤销该次移动。没有重新执行照片或 MP4 导出。

### 物品瞄准（2026-09-28）

- 实时取景和相机属性提供“瞄准物品”：列表绑定物品包围盒中心，“在场景中点选”绑定物品局部位置。沿用原相机架的 Aim 目标求解，物品移动时两端共用同一目标；自由相机首次成功绑定时建立 Dolly 架，取消点选不改文档。
- 点选不再依赖时间轴打开，记录发起操作的相机。拦截按下和松开事件，避免系统在 pointerup 合成的物品选择切走相机；空白处不确认，Esc 取消。只读、锁定、播放和输出期间禁用。
- 支持重新瞄准中心、解除绑定并保留求解姿态；目标删除时提示重选或解除。原瞄准强度和 2D 旋转锁定保留，朝向跟随关闭时提供显式启用入口。
- 原生 Chrome / localhost:3002：时间轴关闭，“相机 1”滑轨架。列表绑定 Staircase 1，预览构图变化并可撤销；刷新加载后场景点选楼梯局部位置，返回相机独立操作且没有切成楼梯选择；解除绑定、两次撤销恢复测试前状态、Esc 取消通过。未重新验收导出。
- 新增回归覆盖自由相机及三种架型、变换父级、物品移动、局部瞄准点、序列化、单步撤销、锁定和只读，以及绑定完成后的 pointerup 隔离。

### 环绕与自由移动对照修正（2026-09-28）

- 原源码 `build_rigs.py` 用 Camera → Aim 的 TRACK_TO 约束实现持续朝向；`operators.py` 的 Shift To Pivot 是移位对齐，没有独立鼠标环绕操作符。自由移动机位时仍会朝向 Aim，因此小幅操作的画面可能与环绕相似。
- 系统原环绕确实保持半径，但俯仰轴错误地取自外部观察相机右轴；侧视时该轴可能接近机位到 Aim 的连线，导致上下环绕退化，斜向拖动也受观察方向影响。
- 现改为固定 Aim 的转台式环绕：世界竖轴改变方位，水平旋转后的机位经线切向轴改变俯仰；半径固定，极点前限制俯仰防止翻转。大世界与取景窗共用同一计算，自由相机的朝向也应用同一个旋转增量。插件原瞄准强度、偏移、2D 约束继续保留，不承诺人为关闭跟随后主体仍居中。
- 与 Blender 的 Turntable 导航概念对照，不宣称此鼠标映射是 Add Camera Rigs 原版操作符。参考：https://docs.blender.org/manual/en/5.0/editors/preferences/navigation.html 。
- 607 项相关回归、81081 个断言通过；新增正面/侧面/俯视和取景一致性、四分之一/半圈/完整圆轨迹、自由移动直线对照、极点及零半径用例。原生 Chrome 已观察到“相机 1”绑定 Staircase 1，但发起拖动前工具报告用户操作，故停止接管，本轮不记为现场拖动验证。

### 正对物品表面与拍照预览导航（2026-09-28）

- 原插件以 3D 游标放置固定骨架，并通过 Aim 约束求解朝向；创建流程没有拾取物品面并自动对齐该面的操作。系统新增“正对表面”：在大场景点选物品表面，沿表面法线摆放相机，并以物品轴投影确定画面上方向。它是显式的一次对齐，不替用户猜测初始正面，也不是移动全过程强制保持平行。
- 对齐重新建立当前类型的相机架姿态，清除旧倾斜、骨架偏移与镜头偏移，保留实际焦距、拍摄距离及对焦设置，绑定点选位置。自由相机成功对齐时建立 Dolly 架。2D 的取景角围绕 Aim 重新居中，避免原框角中心与 Aim 不同造成初始斜视；支持单步撤销。
- 修复拍照“相机”面板只有渲染和点选对焦、没有鼠标导航的问题。现在该面板与自动实时取景调用同一导航函数：左/中键移动机位，右键环绕，滚轮推拉；保持原控制骨、约束和驱动。相机控件在开始操作时切到“机位”，主场景观察视角保持独立。
- 导航校验当前画布所有权、活动相机、面板收起及时间轴状态；换相机、收起、画布被接管时取消未完成操作。焦点拾取仍优先，连续滚轮一次撤销。新增三种架型在拍照预览中往返推拉、撤销与取消回归。
- 正对表面覆盖自由相机和三种相机架、立方体三个方向、旋转/非均匀缩放父级，以及镜像父级下的正交画幅保持；校验实际朝向、上方向、距离、焦距、镜头居中及撤销。
- 本轮原生 Chrome 已确认“正对表面”入口加载到两个预览面板。用户继续切换相机、操作轨迹，工具在滚轮验证前报告用户操作，因此未继续接管；不将当前轮的对齐和拍照窗口滚轮标为现场实测通过，也未撤销用户操作。

### 机位推拉控件的拖动方向（2026-09-28）

- 用户指出的是机位旁“自由移动 / 环绕瞄准点 / 推近、拉远”中的直接推拉。原处理只读取垂直位移，水平拖动不产生运动；现在按最初拖动的主方向锁定横向或纵向，左 / 上推近，右 / 下拉远，避免另一方向的手抖反转推拉。3 像素内的点击抖动不修改相机，Shift 精调保持连续。
- 保留机位到 Aim 连线上的距离计算、原控制骨与镜头联动；取景窗滚轮继续使用同一推拉运动计算。
- 直接拖动与取景导航共 63 项测试、486 个断言通过；编辑器类型检查通过。
