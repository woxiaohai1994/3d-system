# 相机原版高级数值输入与拖动复测

本轮在前台 Chrome 的 `localhost:3002/scene/4d3b26be8028` 测试，未操作用户另一个场景标签。测试相机为“相机 1”、滑轨相机架、焦距 24 毫米、景深关闭。基线机位和瞄准位移/旋转为零，缩放为一。所有测试变换均取消或撤销；最终旋转中心恢复质心，工具恢复移动。

## 已观察的实际操作

| 操作 | 实际结果与恢复 |
| --- | --- |
| G、X、首次 `*`、输入 `2+3` | FULL 的首次触发不插入字符；HUD 显示原字符串与值 5。回车后机位原通道为 `[3.536,-3.212,-1.477]`，反映世界 X 位移 5 的原骨架转换。一步撤销回零。 |
| R、Y、FULL `pi/2`，再补 ` rad` | 无后缀先按原默认度求值约 1.57°，加 rad 后为 90°；对应机位旋转通道从 `[-.008,-.656,1.427]` 到 `[-24.684,-24.684,90]`。退出键全部恢复零。 |
| S 中原生粘贴 `2+3` | 不必先启用 FULL；回车后机位缩放三轴都是 5，一步撤销回 `[1,1,1]`。 |
| S 中粘贴 63 个内容字节 | 原容量拒绝，字符串仍空，未遗留“正在计算”。随后输入 3、回车，三轴都是 3；一步撤销回一。 |
| G、Y、FULL `sqrt(9)` | HUD 为 3，机位位移显示 `[0,-1.253,2.726]`，对应世界 Y 位移 3。按 Cmd+C 后立即退出，进入 S 再 Cmd+V，HUD 保留 `sqrt(9)`，三轴缩放为 3；退出恢复基线。验证复制不是等计算完成才执行。 |
| S、FULL `2+`，再补 3 | 无效算式显示中文“无效”，三轴保留最近有效值 2；补完整后立即变成 5。退出回一。 |
| 完成算式后拖机位上方箭头线框 | 自由拖动写入机位 `[1.230,.154,.826]`，没有出现普通模型三轴工具；一步撤销回零。 |
| 光标吸附到瞄准，旋转中心为三维光标，拖机位线框 | 相机围绕目标移动，蓝色瞄准中心保持原屏幕位置；机位位置为 `[1.614,.176,.944]`，旋转 `[-10.813,-59.777,18.701]`。一步撤销。 |
| 光标吸附到机位，拖瞄准旋转线框 | 目标围绕相机移动，机位位置固定；瞄准位置 `[1.157,-.075,-.404]`，旋转 `[-2.947,38.284,-8.478]`。一步撤销后检查机位通道仍全部为零。 |
| 实时取景窗拖瞄准上方箭头 | 瞄准位置 `[1.664,0,-1.243]`，场景与取景同步；一步撤销回零。 |

线框来自原插件的控件数据。旋转和缩放中心、G/R/S、方向约束和数值输入属于 Blender 宿主变换规则的适配；没有把这些称为插件另带的三个独立移动轴。

## 本轮发现并修复的问题

- 读剪贴板 API 会弹出额外权限框并使手势失焦。改为 Ctrl/Cmd+V 的原生粘贴事件，使用临时有中文标签的数值粘贴目标；不申请剪贴板读取权限。
- 粘贴容量拒绝后，只改手势对象但没重新发布状态，界面克隆一直显示 pending。现清除并发布状态，并跳过再次处理同一个没有剪贴板内容的按键，避免 Ctrl+V 意外将缩放写为零。
- FULL 复制原先被延后到异步计算结束，随后退出会丢失复制。现按照原函数顺序先复制一次，再等计算。
- 输入框内的粘贴以及取消后迟到的粘贴不能进入相机手势。两条独立事件复测及持久回归测试通过。

一次计算机操作工具向 G/Y 粘贴 `sqrt(9)` 报“等待应用读取剪贴板超时”，该次不算通过。随后改用实际 FULL 输入、Cmd+C、退出、S、Cmd+V 的路径，确实观察到相同算式和值。首次加载 Worker 曾暂时显示“正在计算”；不能把等待画面当作结果。
