# 灯串创建器：可行性与能力复用调研

核查日期：2026-09-20；2026-09-21 根据用户修正更新灌木模式，并核查新增模型入库与内置 AI 接入。状态：源码与官方文档调研、建议方案；未实现插件，未做灯串运行、导入样品或性能实测。

## 结论与产品定义

可以基于现有 Pascal 插件 API 实现，已具备开始开发的条件。建议一个独立插件，提供路径灯串与区域散布两种模式，共用「导入模型单元 + 排列/朝向/颜色/动态规则」。路径模式增加可编辑三维路径与多挂点约束；灌木模式只随机分布灯泡，不生成或显示线缆，也不要求隐藏的连续走线。C9、S14、左右双灯仙女灯、线上居中灯是配置预设，不是四套工具。创建方式与灯型分开，同一条路径可换款而保持挂点与布置。

导入模型决定几何外观；路径决定安装位置；规则决定数量、分布、朝向与灯效。灯泡、灯座、夹子、地插等刚性零件应保持形状，线缆由插件沿路径生成。不能把含多个灯泡、线缆的任意整体模型直接弯曲后，宣称仍可独立调节灯数、间距并保持零件不变形。

## 外观单元与预设

| 预设 | 重复单元 | 默认朝向规则 | 必要参数 |
| --- | --- | --- | --- |
| C9 | 用户导入的灯泡、灯座和夹子/地插组合 | 保持校正后的模型方向、世界竖直、或沿安装表面法线 | 接线点、安装点、离面偏移、绕轴角 |
| S14 | 用户导入的灯泡与灯座，可带固定短吊线 | 重力向下；接线位置随主线走 | 吊线长度、摆角、朝向偏移 |
| 左右仙女灯 | 单灯模型，或预制的一对灯单元 | 路径两侧，成对或交错 | 左右偏移、错位距离、支线长度 |
| 居中灯 | 接在线中的灯珠/灯座单元 | 沿路径切线 | 进线/出线连接位置、模型轴向 |

模型注册时一次性确认：尺寸单位、模型校正变换、一个或两个接线点、安装点、发光网格/材质、可变色部位。已有 Asset 的 src、dimensions、offset、rotation、scale 可以承接通用信息；连接点和灯光部位另存灯串专用描述。无需要求用户必须回建模软件改原点；可提供预览中点选标定。

若用户导入整条灯串：层级可分离时由用户选择可重复单元；合并成单一网格时需预处理或作为固定组合模型使用。不要自动把夹子变地插，缺少配件必须提供对应模型。默认保留导入材质，仅对已指定的灯泡部位应用变色/发光。

## 创建方式与难度

| 使用场景 | 建议实现 | 判断 |
| --- | --- | --- |
| 栅栏两端悬挂 | 两个固定挂点之间生成悬链线/受控近似曲线 | 常规可实现；需要新增下垂计算 |
| 中途增加挂点 | 将相邻挂点作为独立跨段，允许逐段设置下垂 | 常规可实现；不能用一条平滑曲线抹掉固定点 |
| 拉直 | 跨段切换直线，保留挂点 | 常规可实现 |
| C9 沿地面 | 沿路径采样地形/承托面，逐灯确定高度和方向 | 有地形/楼板能力可复用，需逐点适配 |
| C9 沿屋檐 | 用户选边或画路径；利用屋顶语义确定挂点/轮廓 | 部分复用；整屋自动寻边不是现成能力 |
| 柱/树干缠绕 | 用户指定轴线、范围、半径、圈数、螺距；可添加表面投射 | 可实现；规则对象优先 |
| 灌木内不规则布置 | 用户选灌木或区域，只随机分布灯泡，控制数量/密度、深度、最小间隔和颜色 | 可实现；不需要线缆、连续走线或穿枝物理 |
| 任意枝叶间自动穿绳 | 不属于当前灌木需求 | 不作为开工或首版交付前置条件 |

柱/树干缠绕仍按实际路径排灯。灌木则直接在指定区域/包络或表面附近采样灯泡位置，不依赖路径。随机结果保存种子及生成版本；手动修改保存位置覆盖，重开项目不能改变原设计。数量或密度二选一为主参数；约束过密时报告实际生成数，不静默重叠。简单包围盒不等于精确灌木体积，需要区域预览、边界与深度调整，避免灯泡散到明显空处。几何重建后无效的模型三角面引用不能继续当作可靠挂点。

Three.js MeshSurfaceSampler 可复用来做表面模式采样；灌木体积/表层厚度、最小间隔和可控分布需要补充轻量逻辑。该工具不提供体积采样，但当前需求也不需要连续走线或真实绳索缠绕。[官方说明](https://threejs.org/docs/pages/MeshSurfaceSampler.html)

## 推荐插件结构

建议独立包（名称待定），主节点保存路径、挂点、样式引用、规则与版本。外部宿主只负责发现、面板注册和构建接线，沿用官方要求的 peerDependencies。[Pascal 插件规范](https://editor.pascal.app/docs/developers/plugins)

业务划分：

- 路径模块：直线、逐段下垂、手绘/控制点曲线、规则缠绕。
- 区域散布模块：灌木目标/区域、数量或密度、深度、最小间隔、固定随机种子，不生成线缆。
- 连接模块：自由点、语义特征点、宿主局部点与法线；记录失联时的最后有效位置。
- 排列模块：按弧长采样，数量/间距二选一为主参数，双侧/交错/居中/下吊为规则。
- 外观模块：资产引用、连接点与材质映射；刚性零件保持原形。
- 渲染模块：路径模式的线缆网格、两种模式共用的灯泡实例与颜色/动画属性。
- 编辑模块：复用宿主选择、拖动、预览、撤销、面板与二维表现接口。

现有 Three.js 提供 Curve 的弧长采样、CatmullRomCurve3 和 TubeGeometry，分别用于按真实线长布灯、自由曲线及线缆几何。需要新增的是灯串约束与规则，而非基础曲线/网格库。[Curve](https://threejs.org/docs/pages/Curve.html) · [CatmullRomCurve3](https://threejs.org/docs/pages/CatmullRomCurve3.html) · [TubeGeometry](https://threejs.org/docs/pages/TubeGeometry.html)

数量模式固定总数后推导间距；间距模式按线长推导数量。左右成对要区分「站位数」和「灯泡数」。跨挂点默认连续编号、连续颜色序列；端部留白、逐段重置可作为选项，防止挂点处重复生成。

朝向单独处理：C9 可保持世界竖直或表面法线，S14 默认向下，居中灯随切线，仙女灯使用稳定的左右局部坐标。直线、拐点、竖直段与闭合路径须避免突然翻转。不要仅靠路径切线来决定所有灯型的安装方向。

场景中一串为一个主要节点，灯珠作为渲染实例而非成千个家具节点。以后可记录按稳定编号/线长位置定义的单灯覆盖，支持点选单灯改色，但整体改密度时须定义覆盖如何保留。Three.js InstancedMesh 支持逐实例变换和颜色；多部件 GLB 需要按子网格/材质分组，发光颜色还需相应材质属性处理，不等于一行 setColorAt 解决所有材质。[InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)

多宿主挂点各自引用对象，灯串主体留在统一坐标框架。移动一个柱子只更新对应挂点及关联跨段；屋檐尺寸变化优先通过语义边/特征重新求点。删除宿主保留最后有效位置并标示失联，可重新绑定。楼层、建筑变换只应用一次；地面灯逐点采样，不能把整条跨坡灯串当一件落地家具整体抬高。

## 颜色、摆动与光源

颜色规则可支持统一色、循环序列、分组重复、渐变、固定种子随机和单灯覆盖。动态规则独立控制亮度/颜色随时间变化。改变规则不重建所有灯泡几何，也不修改缓存的原始资产材质。

用户说的摆动幅度建议拆为静态自然偏差和动态风摆：前者形成不齐的朝向/位置，后者随时间运动。固定挂点的动态位移应为零，地插/夹紧的部位默认不摆，悬挂部分允许摆动。展示级自然摆动可先实现；不宣称具备绳索受力、枝叶碰撞、自碰撞的实时仿真。

灯泡发光外观与照亮周围分开：所有灯泡可表现发光，真实光源按全场景预算提供。优先适配既有共享光源池；确需额外能力再做通用扩展。大规模彩色灯串、透明灯罩、阴影及导出均需真实样品实测，不能预先给出稳定帧率或灯数承诺。

## 实施顺序与验收

1. 验证基础闭环：用真实 C9、S14、仙女灯样品完成模型标定、直线/多挂点下垂、换款、间距/数量、颜色规则、保存重开、单步撤销。确认模型保持形状、配件没有被错误染色。
2. 完成日常布置：地形与屋檐/栅栏挂点、手调三维控制点、拉直、局部下垂、规则缠绕、静态自然偏差及简单动态效果；实现适用的二维编辑对应行为。
3. 完成植被布置：用户选灌木/区域随机散布灯泡，不显示线缆；支持深度、疏密、局部调整与固定随机种子。该模块不依赖复杂缠绕，可以提前与路径模式分别开发。

验收必须覆盖：挂点移动/删除、父级旋转缩放、跨段灯泡间距、极短/竖直/闭合路径、数量模式切换、模型更换保留布置、资源缺失、取消和撤销、保存重开、插件停用再启用、静态导出。不同灯泡规模分档记录帧率、绘制调用、内存与编辑延迟；这属于后续实现验收，本次未运行。

## 内置 AI 接入与开工条件（2026-09-21）

结论：可以开工，建议首版就包含内置 AI 的创建与修改接口。已有 AI 配置、模型入库、资料分析、统一目录、聊天工具循环、场景预览和事务可复用；灯串及散布能力本身仍需开发。

### 当前核查结果

- apps/editor/components/ai-panel.tsx 将 ModelLibraryProvider 接入当前 AIProvider；不是旧 integrations/ai/scene-tools.ts 的少量家具工具模块。
- ModelLibraryProvider 读取宿主模型记录，把已发布资产交给 setCatalogAssets，并排除未发布/已删除记录；模型库与内置 AI 使用同一来源。
- /api/ai/assets/analyze 复用当前 AI 配置。handlers.ts 当前输入是用户资料、文件名、部件名和程序统计；提示词明确没有看到图片。不能将目前的资料识别描述成已经自动看懂任意灯泡网格、接线点或发光部位。
- 当前 modelMetadataSchema 是严格结构，包含名称、分类、标签、安装方式、单位和旋转校正，没有灯串接线点/排列类型/发光部位字段。建议插件保存引用资产 ID 与校准版本的样式描述，不把专用字段随意塞进现有 schema 后假设会保留。
- 内置 AI 工具来自 components/ai/prompt/openai-tools.ts；tool-validation.ts 从固定表创建名称与参数校验。服务端 integration-ai/protocols.ts 导入该工具表，ai-mutation-executor.ts 通过 switch 分派，ai-scene-serializer.ts 按既有对象类型整理上下文。
- 因而 plugin NodeDefinition.mcp 说明不等于自动注册到当前内置 AI。需要显式接通工具声明、服务端/客户端校验、执行分派、场景摘要、预览与结果回传；仅加提示词无法完成。

### 最小接入方式

插件导出无 UI 的参数与命令逻辑、编辑面板和渲染器。手动操作与 AI 调用同一组「创建灯串、修改灯串、区域散布、读取配置」命令；命令产出候选场景变更，经既有校验和预览事务执行，不逐颗调用 add_item。

建议在宿主 AI 侧提供小型通用贡献接口，接收工具 schema、对象摘要和命令适配器；该接口目前是拟新增能力，不是 Plugin API v1 自带字段。服务端与客户端读取同一套受信任的工具定义，按当前项目启用插件暴露工具，停用后拒绝执行；不在每个插件中重新维护协议、密钥、聊天和历史。如沿用固定表完成首个接入，也应将插件参数与执行规则保持在插件导出模块中，避免复制两套规则。

拟新增工具示例（未实现）：

| 工具 | 作用 |
| --- | --- |
| create_string_lights | 按明确资产/样式、目标挂点和参数创建路径灯串 |
| update_string_lights | 修改间距、数量、下垂、颜色序列、灯效或样式 |
| scatter_bulbs | 在选中灌木/明确区域内随机分布灯泡，线缆关闭 |
| inspect_lighting | 返回目标对象、模式、样式、数量、颜色、挂点或区域配置 |

AI 获取当前选中对象的 ID 与区域/路径能力后，提交用户意图和少量参数；插件负责位置生成、弧长分布、确定性随机与数量限制。对象不明确时询问或提示选中，不能凭空发明灌木/屋檐节点。后续修改只影响指定灯串或散布组。
