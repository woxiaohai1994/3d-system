# 通用模型表面交互

2026-09-21。此次增强提供表面查询公共接口，并以灯串的创建、三维挂点拖动、二维原宿主保留作为首批消费者。普通物件已有的桌面承载、墙面放置和漫游规则未改动。

## 分层与接口

- `@pascal-app/viewer`：`createSurfaceQuery()` 接收世界坐标 `Ray`、`{id, object}` 目标列表和可选距离/排除条件，返回最近的可见网格交点、世界法线、宿主局部坐标、宿主 ID、网格和实例编号。没有 editor 状态依赖。
- `@pascal-app/editor/surfaces`：`querySceneSurface(ray, {targetIds?, excludeIds?, levelId?, far?})` 从当前场景注册表解析模型；`sceneSurfaceTargets` 提供同样的候选筛选。
- `projectSceneSurfacePoint(point, distance, options)` 在给定世界距离内沿六个轴向查询，选择最近命中。用于保留临近表面，不是任意网格的精确最近点求解器。
- 核心数据层没有引入 Three.js。调用方保存节点 ID 和局部位置，不能将返回的 Object3D 写入场景 JSON。
- `registerSurfaceSource(owner, factory)` 为批量渲染且注册节点内没有可查询网格的模型提供懒加载、脱离场景的 owner-local 几何源。查询时同步 owner 世界变换，隐藏/排除仍检查 owner，返回清理函数。查询源不渲染、不进入导出和原生拾取。内置植物通过既有依赖补丁安装机制接入，复用缓存几何与材质；补丁位于 `patches/localization/plugin-trees.patch`，沿用版本与内容哈希校验。

```ts
import { querySceneSurface } from '@pascal-app/editor/surfaces'

const hit = querySceneSurface(pointerRay, {
  targetIds: selectedModelIds,
  excludeIds: [movingNodeId],
  levelId,
})
if (hit) {
  // 插件/工具决定如何对齐、偏移与附着；查询本身不改变场景。
  previewAt(hit.point, hit.normal)
}
```

`targetIds` 省略表示当前范围全部物理模型，空数组表示没有目标。失效的限定 ID 不会回退到其他模型。选中父对象时包含其后代，但返回命中的最内层已注册物理节点，便于正确跟随子对象。排除条件覆盖整棵子树；隐藏节点、隐藏祖先、幽灵预览、辅助图层、完全透明拾取材质都不成为挂点表面。自定义辅助网格可设置 `userData.excludeSurfaceQuery = true`。

查询使用已有场景网格与 raycast 实现，包括已有 BVH 加速。沿用系统表面图层规则，因此批量渲染的源模型也能查询；不缓存可能被替换的注册表对象，也不修改材质或输入射线。法线处理网格与实例变换，非均匀缩放使用法线矩阵。射线遵循原材质的正反面设置；蒙皮变形、透明贴图像素边界与动态实例的持久附着不在本次验收范围。

## 灯串交互

- 原生选中模型后启动创建，自动限定模型并吸附；两点完成后选中新灯串，原生浮动操作提供拉直、自然下垂、缠绕。名称搜索与目标限定仅作为默认折叠的详细设置。
- 创建/三维拖动优先使用真实表面交点，避免网格吸附将点移离表面；明确限定目标后，未命中时不改挂点。Alt 可自由移动并解除该挂点绑定。
- 灯串组互相排除，避免挂点循环依赖。其他灯泡、颜色、间距参数保持不变。
- 拖动时用实时覆盖，松开提交一次；取消清除覆盖。重新绑定时以当前可见位置重建其余挂点参考，避免其他已跟随移动的挂点回跳。
- 二维无法从投影唯一确定树干前后或檐口上下，故不新增三维宿主；有已加载宿主时，在原表面 0.15 米内保留绑定，移出或 Alt 拖动解除。没有三维宿主时保留原有平面编辑行为。二维新建仍是平面布点；设置目标限定的路径需在三维创建或取消限定。
- 挂点绑定跟随对象刚体变换。改变模型几何形状不会自动重投影；删除宿主后采用保存的点，不承诺保留删除前的临时可见位置。

## 范围

共享层提供表面查询和批量模型查询源。插件已进一步实现批量挂点、灯串混合、沿引导线贴合、按真实截面缠绕与中心线相交检查；详细验收见插件 `docs/interaction-upgrade.md`。复杂树冠/分叉仍可能失败；未实现完整灯泡体积防穿透或软绳受力模拟。其他物品工具可复用公共查询接口，原先放置规则保持不变。

## 参数变形附着（2026-09-21）

本节更新上文“仅跟随刚体变换”的范围。core 新增 `PointAttachment`、`capturePointAttachment`、`resolvePointAttachment`，通过节点定义的 `extensions['pascal:point-attachment']` 接入。提供者的 `capture(node, localPoint, nodes)` 返回可序列化参数及候选距离，`resolve(node, parameters, nodes)` 返回当前宿主局部点或 null。公共层不依赖 Three.js；节点实现复用自身已有的曲线和屋顶表面函数，灯串只消费接口。

- 屋顶段支持坡度、宽深、出檐和面板厚度变化；屋顶组合节点选择支持的子段。侧檐近边点保留固定边距，避免扩大屋顶时边距同比缩小。切换屋顶类型或修改裁切轮廓会使绑定失效。
- 墙和围栏支持沿曲线的相对位置、高度及厚度变化；围栏另复用现有承载标高逻辑。此绑定不是栏杆柱位、门窗洞口等细节的语义绑定。
- 导入 item 支持节点 scale 变化；更换 asset.src 后失效。其他节点仍只有原来的位姿跟随，需按同一接口补充变形提供者。
- 解析使用实时参数覆盖，二维依赖同时包含真实附着子段。读取不写场景，提交和撤销沿用宿主历史。
- 旧灯串在下一次编辑提交或重新附着时补充参数绑定；不会后台改写所有旧场景。失效绑定保留原始坐标回退，并在插件面板提示重新附着。

这不是网格拓扑追踪或变形后的全场景碰撞系统。复杂合并屋顶、替换模型、树木分叉改变和围栏柱样式变化仍需单独适配/验收。

新增 `tests/integration/string-light-attachment.test.ts` 覆盖六种屋顶、墙、曲线围栏、导入模型缩放、二维/三维一致、实时覆盖、序列化及固定檐边距离。连同整串移动和原有专项共 122 项测试通过；插件类型检查、节点构建和应用生产构建通过。

## 整串变换后的附着重建

`NODE_UPDATE_EXTENSION`（`pascal:node-update`）允许节点提供纯函数 `NodeUpdateReconciler`，在普通/批量/原子更新中返回本节点的派生字段。输入包含 previous、next、patch、previousNodes、nextNodes；读取完整批次的新旧快照，每个节点最多执行一次，派生补丁一起验证和写入原历史提交。禁止修改 id/type/parentId/children；回调不得写场景或依赖实时渲染对象。撤销和重做恢复已有快照，不再次执行此推导。

灯串用此接口把整串移动/旋转后的可见路径重新记录为当前宿主局部附着点。解析旧路径时读取提交前快照，重新绑定时读取提交后快照，避免批次里宿主和灯串一起移动造成重复位移。显式修改路径或挂点的操作保留其自带坐标；混合灯串仍采用原混合逻辑。父容器切换尚未纳入该变换重建。

验证：灯串专项 126 项通过；核心更新、数值验证、图链接、原子计划及历史回归 367 项通过。整串微调、后续宿主旋转、再微调、二维/三维坐标一致、单次撤销/重做及 JSON 重载均有集成断言。批量一起移动的证据覆盖提交结果，尚未独立验收组合拖动的中间预览帧。

## 圆形与多边形柱身参数跟随

柱节点接入同一个点附着协议。`column/shaft-profile.ts` 从原渲染器抽出柱身分段、轮廓、扭转和基座/柱头之间的高度计算，渲染器与附着共用。圆形、八角、十六边柱身记录段内位置、相对角度及径向离面距离；改变高度、半径、柱身轮廓和分段扭转后重新解析，离面距离不随尺寸放大。

当前仅支持没有附加雕刻、环带等装饰的这三类竖向柱身。方/矩形柱、基座、柱头、支架和簇柱未接入；改变截面类型、分段数量或增加不支持的装饰会使已有参数绑定失效，沿用重新附着提示，不猜测新表面。

`tests/integration/string-light-column-attachment.test.ts` 挂载实际柱渲染器，从真实网格射线交点捕获绑定，改变高度、半径、基座/柱头高度、鼓形和扭转后再次射线核对，三种截面均保留 0.04 米径向距离，另覆盖序列化和失效回退。完整相关回归 131 项、12559 个断言通过；节点构建、宿主类型检查和生产构建通过（`/tmp/string-light-column-*.log`）。

## 内置树高跟随与跨插件保存

树木定义通过现有依赖补丁接入点附着扩展，使用树木 renderer 的等比例高度变换，无需加载 ez-tree 或 Three.js 即可解析。树高改变时，已附着路径在树木局部空间同比缩放；灯泡尺寸、沿线间距、颜色等产品参数不变。树种、规格、随机种子、生长类型、树干粗细或枝叶参数改变会触发重新生成几何，因此令旧绑定失效。尤其树干粗细会参与枝干弯曲计算，不能简单将挂点横向缩放。树皮、树叶颜色修改保持绑定。

页面发现原始 `trees:tree` 标识被保存 API 的外来节点 URL 扫描当成 URI 拒绝。现在附着协议的 `kind` 保存 `encodeURIComponent(node.type)`，解析比较相同编码的宿主类型；未改动或放宽 API URL 校验。内置无命名空间类型的编码保持原值。新增测试将真实树木附着灯串送入 `apiGraphSchema`，同时确认附着参数中的危险 URL 仍被拒绝。

`tests/integration/string-light-tree-attachment.test.ts` 覆盖六种树木预设、二维/三维坐标、实时覆盖、单次历史、撤销、JSON 恢复、颜色编辑和几何重建失效。加上保存边界及原有相关回归共 149 项、12668 个断言通过；核心构建、宿主类型检查和生产构建通过。树木依赖补丁在临时目录完成反向/重新应用及所有前后哈希验证。

浏览器场景 `4323f931cb8c` 中，树干缠绕灯串的 161 个挂点已通过正常编辑保存参数绑定（服务器读回确认）。树高 5→7 米时缠绕跟随，面板路径长度 4.30→6.03 米；按固定 0.350 米灯距计算的灯数 13→18，灯泡仍为 0.045 米。随机树形变成种子 89 后，灯串面板出现重新吸附提示；撤销后消失。高度和随机树形测试修改均已撤销，保留升级后的绑定。

此阶段尚未实现树木枝干重新生成后的自动路径重建，也未把 GPU 风摆纳入绑定计算；树高等比缩放会同比改变路径离面距离，并不等于重新执行体积防穿透检查。

## 树干粗细与枝叶变形跟随

本节扩展上节“树高跟随”的范围。viewer 增加 `createMeshPointAttachmentProvider`：复用表面查询的缓存间接 BVH，捕获最近三角面的重心坐标与局部切线/法线偏移；同一语义网格且索引拓扑保持一致时，在新几何上解析对应位置。调用方负责提供稳定语义键；拓扑摘要包含顶点数及完整索引顺序。该接口不识别任意替换模型，也不追踪重排后的三角面。

树木几何保留枝干/叶片语义标记，复用现有树木变体缓存。原绑定保存的形状参数用于取得原始枝干表面；树干粗细、枝叶密度、无叶状态改变时，按对应枝干三角面重建挂点，保留离面偏移。接近叶片而远离枝干的点不会被强行拉到树干。树种、规格、生长类型、随机种子改变仍返回失效，继续提示重新吸附。定义仅在浏览器遇到变形时同步加载几何模块，避免 ez-tree 的模块级纹理加载破坏 SSR；无 DOM 的纯服务端变形解析返回 null。GPU 风摆与变形后的全场景防穿透仍不在范围内，树高等比缩放的既有行为保持不变。

新增网格测试覆盖间接 BVH 的三角面对应、索引不被改写、顶点更新、非索引网格、拓扑失效、旋转变形及物理偏移。树木集成测试实际运行 ez-tree 六种预设生成器，仅替代纹理图片加载，从实际枝干网格射线交点绑定，改变粗细、枝叶和无叶状态后核对对应三角面。测试射线避开网格接缝，避免把相邻面的正常最近点选择误判为位移错误。

页面场景 `4323f931cb8c`：在树木原生面板把树干粗细 1.0 改为 1.8，161 个缠绕挂点继续有效，路径 4.30→6.47 米；固定灯距 0.350 米、灯泡尺寸 0.045 米保持不变，灯数按路径长度变为 19。切换二维显示同一条变形路径。服务器保存读回仅树木属性改变，未重写灯串产品数据。一次撤销后服务器 graph 与测试前完全一致（版本 91→93），最后恢复三维视图。

## 公共算法与模型几何共用

用户要求避免每种物品重复实现交互。公共层已经承担点附着协议、表面查询、BVH 缓存、稳定网格对应、实时覆盖及历史联动；模型只提供可复用的几何来源，或在改变结构时提供语义对应规则。接入旧模型的几何来源与为每个模型重写算法是不同工作。现阶段尚未把全部历史 renderer 的 JSX 几何自动转成这种公共来源，不能声称所有种类均已支持任意参数变形。

方/矩形柱的柱身构造已从 renderer 抽到 `column/shaft-geometry.ts`。实际渲染与通用 `createMeshPointAttachmentProvider` 共用同一缓存网格，删除 renderer 内重复的圆角拼接代码。保持原有几何函数、柱身轮廓、分段扭转及 UV；同一材质的柱身部件合并渲染。普通方/矩形柱支持宽深、高度、轮廓、圆角和扭转变化，仍遵循无附加雕刻等装饰的支持边界；分段数变化或圆角导致网格结构改变时返回失效。

实际挂载 renderer 的测试覆盖原有圆/多边形柱和新增方/矩形柱，变形后向真实表面发射射线，确认 0.025 米离面距离。另使用临时保存的改造前 renderer 做 12 组外观对比，全部顶点、法线与 UV 差异小于 1e-6；临时基准代码验证后已移出工作区，日志保留 `/tmp/string-light-shaft-renderer-parity.log`。相关集成回归 54 项、1047 个断言通过，节点构建、宿主类型检查、应用生产构建通过（`/tmp/string-light-shared-shaft-*.log`）。浏览器重载场景正常；本轮未向用户场景写入测试参数。

## 统一几何入口核查与重开验收

当前 `GeometrySystem` 已通过 `NodeDefinition.geometry(node, ctx)` 统一构建模型；块体、搁架、柜体、楼板和多种机电对象采用此入口。它是后续公共表面源的复用入口，不需要在灯串插件里复制每种物品的几何。`geometryKey` 是重建缓存键，包含尺寸甚至材质，不能直接当成永久附着身份。`buildBlockGeometry` 已保留语义面 ID（`geometry.userData.blockFaces`），但 `triangulateBlockFace` 会重新三角化面；不能因顶点总数没变就认定旧三角面序号仍指向相同位置。统一来源还需提供稳定部件/面身份与变形对应，或者明确报告失效。现有 `PointAttachmentProvider` 允许这些模型语义规则与公共网格跟随共存；未在未经验证的所有 `def.geometry` 上强制启用三角面持久绑定。

## 公共稳定面与顶点对应

`AttachmentMesh.triangles` 可提供与渲染三角面顺序一致的不可变标识数组，每项含 `faceId` 和三个 `vertexIds`。公共网格附着算法保存语义身份及原顶点顺序，在新几何上查找同一三角面并恢复重心坐标和物理离面偏移。因此，三角面/顶点数组重排、无关三角面的增删不再必然导致失效。缺失、重复或含糊的身份返回 null；没有这些标识的旧提供者继续使用原拓扑摘要检查。调用方必须在拓扑变化时替换标识数组，并保证语义键不被无关替换模型复用。

块体通过 `getBlockSurface` 暴露原有几何构造及已有持久面、顶点 ID，实际渲染与附着使用同一来源。渲染输出克隆几何，以隔离 GeometrySystem 的销毁周期；材质分组、法线、UV 和绘制面元信息保留。块体定义仅注册公共提供者，没有新增块体专属跟随算法。若原三角面因重新剖分、面删除或顶点替换而消失，仍会失效；本次不包含任意多边形重新三角化的连续映射。

## 复制时重映射插件引用

## 复制时固定派生形状与跨楼层依赖

core 新增 `NODE_COPY_EXTENSION`（`pascal:node-copy`），提供纯函数 `snapshot(node, nodes)` 与 `finalize(source, clone, idMap)`。前者在复制时读取依赖并记录派生数据，后者在图链接和声明引用重映射后处理新容器的依赖关系；两者均只返回本节点字段补丁，不允许改写 id/type/parentId/children。整场景、楼层、子树和剪贴板复制共用这套生命周期。Scene API 传入完整源场景，使单独复制子树也能读取外部宿主。剪贴板在复制时拍快照，不等到粘贴时再读取已变化的原场景。

灯串接入后，同容器复制保留外部绑定；跨容器复制仅保留一起复制的宿主及实际附着子节点，未复制的宿主解除绑定并保留复制时的路径。混合灯串只有两个边界同时复制才保留混合关系，否则固定当前混合结果。跨楼层粘贴沿用系统原有目标楼层局部坐标约定，随目标楼层整体抬高，不承诺保持原楼层世界坐标。这不包含直接修改已有节点 parentId 的重新挂接，也不包含任意跨楼层外部附着解析。

## 跨楼层与建筑坐标一致性

公共 `nodeSceneFrame` 在既有 `nodeLevelFrame` 上组合楼层累计标高和建筑变换，复用 `getLevelElevations`，不另写楼层堆叠算法。它返回物理场景坐标，不包含爆炸楼层视图的临时分离距离。对于已被编辑器展平为楼层局部坐标的临时姿态，可显式传入 `coordinateLevelId`，避免丢失楼层标高或重复计算父对象变换。

灯串的纯坐标解析、复制快照和附着重建改用同一公共坐标系。依赖收集补齐相关建筑内的楼层，楼下层高变化也能更新楼上宿主的位置；通过 `GeometryContext.sceneNodes` 与 `resolve` 同时保留源坐标系和实时覆盖。额外捕获并修复了“抬高且旋转建筑内，二维宿主拖动预览错误地被当作世界坐标”的回归，新增用例已验证修复前失败、修复后通过。

普通附着灯串直接改变父容器时，不再跳过重建：先取更新前的可见路径，再按新容器和显式 position/rotation 重建绑定，与普通模型改变父级的局部坐标语义一致。这不自动保持旧世界位置；调用方若要保持世界位置，应一并提供转换后的局部位姿。只移动宿主到另一层时，原挂点仍跟随宿主。混合灯串直接换容器的边界关系处理仍沿用原校验/提示，未纳入这次普通附着修复。
