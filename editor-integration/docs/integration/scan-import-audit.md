# 扫描导入功能与模型入库的差距

核查日期：2026-09-20。范围为当前独立应用的扫描入口、文件保存、节点结构、渲染、AI 与导出代码，以及本地测试和隔离复现。本轮没有修改业务功能、调用外部 AI 或操作用户场景，尚未完成浏览器真实文件上传和重开验收。

## 1. 结论

“扫描”确实可以导入已有三维模型文件。当前实现定位是楼层中的参考模型：从文件选择器读入 GLB/GLTF，保存到当前浏览器的 IndexedDB，创建 `ScanNode` 并显示。

它提供了可复用的文件接收、基础保存、加载和变换功能，但不等于资产库入库。扫描对象没有资产分类、标准宽高深、材质部位、产品/款式关系和版本引用，也没有进入当前 AI 模型目录。

建议复用上传和预览基础，保留扫描参考用途，增加“加入模型库”流程。不要把全部扫描节点直接视为家具，也不要仅改中文名称后宣称已完成入库。

## 2. 当前能做什么

| 项目 | 当前实际实现 | 限制 |
| --- | --- | --- |
| 文件入口 | 楼层下“Upload scan/floorplan”按钮，接受 `.glb`、`.gltf` 和图片 | 每次读取一个文件；无模型批量入库或目录发布 |
| 大小限制 | `200 * 1024 * 1024` 字节，界面称 200 MB | 只限制文件大小，不代表解析、渲染或性能检查通过 |
| 类型分流 | GLB/GLTF 创建 scan；图片创建 guide | 不直接接受 FBX、OBJ、Blend 或原始点云文件；图片不是三维扫描模型 |
| 本地保存 | `saveAsset(file)` 写入 IndexedDB，返回 `asset://...` | 当前应用未注入 `onUploadAsset`，没有走宿主文件上传后端 |
| 场景登记 | 系统生成 scan ID，以去扩展名的文件名命名，挂到选定楼层 | 这是场景节点编号，不是永久资产编号 |
| 初始变换 | 位置 `[0,0,0]`、旋转 `[0,0,0]`、统一缩放 `1`、不透明度 `100` | 未测量或自动规范化单位、正面、底面和锚点 |
| 渲染 | `ScanRenderer → useAssetUrl → useGLTFKTX2`，沿用 GLTF 加载及现有压缩解码配置 | 实际能否加载取决于文件与依赖；导入完成状态先于渲染验证 |
| 手动编辑 | 重命名、显示/隐藏、删除、移动、XYZ 位置、绕 Y 旋转、整体缩放、透明度 | 普通参考面板未提供扫描换文件、分类、材质切换或产品换款 |
| 节点能力 | 可移动、旋转、缩放、删除；`duplicable: false`、`presettable: false` | 没有普通物件的承载、挂载和碰撞足迹声明 |
| 保存场景 | 场景图记录 scan 节点及 `asset://` 引用 | 文件字节仍留在浏览器数据库，不会因 JSON 场景保存而自动进入宿主模型库 |

## 3. 容易混淆的五件事

### 3.1 文件导入，不代表自动扫描重建

当前入口读取已经存在的模型文件，没有在这条流程中通过摄像头、照片或 LiDAR 自动生成网格。核心 schema 和 viewer 另有采集会话、轨迹、点云/表面层的基础设施；这不能证明当前独立应用已经接通手机采集、重建或完整采集会话上传。

### 3.2 GLTF 后缀被允许，不代表其依赖一起导入

文件选择器每次只取 `files[0]`，保存函数只存该文件，不收集同目录 `.bin` 和纹理，也未建立依赖映射。内嵌资源的文件与依赖可直接访问的文件可能加载；依赖本地同目录文件的 GLTF 不能据后缀支持而承诺成功。GLB 也应检查依赖完整性。

### 3.3 能缩放，不代表已测得并登记真实尺寸

`ScanNode` 保存 position、rotation、一个统一 scale 和 opacity，没有 dimensions。当前上传函数不解析几何边界，参考属性面板没有标准宽高深入库结果。

这不意味着三维几何不可测量：可以加载后计算边界，再按单位和校正变换得到基准尺寸。需要补的是测量、异常检查和记录流程。当前扫描网格禁用了自身 raycast，2D 量测吸附也跳过 scan，不宜把通用量尺直接当作扫描尺寸自动提取能力。

### 3.4 本地保存，不代表跨电脑保存

在相同浏览器配置与相同站点来源下，IndexedDB 可以保留文件；仍需要有效的场景记录来找回引用。清理网站数据、换浏览器、换端口/站点或换电脑后，场景 JSON 中的 `asset://` 不会携带原文件。当前主页还是明确标记的空白工作区，不能据本地文件已保存就承诺整个主页场景重开恢复。

此外 scan 的 `bake: 'strip'` 会被当前场景 GLB 导出准备流程排除。导出场景 GLB 不能作为“已把扫描文件一起带走”的证明。支持该图的 viewer 可以在有源资源时另行加载参考节点，但普通 GLB 文件自身不因此包含扫描资产。

依据：[场景保存](../../apps/editor/components/scene-loader.tsx:140)、[JSON 导出](../../packages/editor/src/components/ui/sidebar/panels/settings-panel/index.tsx:354)、[GLB 导出排除策略](../../packages/editor/src/lib/glb-export.ts:388)。

### 3.5 上传成功，不代表可供 AI 使用

当前目录扫描器仅合并 `node.type === 'item'` 的资产，scan 不在内。AI 场景摘要的节点分派也未加入 scan 资料。因此，导入扫描后点“刷新模型”不会把它自动变成可被 `add_item` 选择的模型库资产。

依据：[目录来源](../../packages/editor/src/components/ai/ai-catalog-resolver.ts:349)、[AI 场景摘要分派](../../packages/editor/src/components/ai/ai-scene-serializer.ts:464)。

## 4. AI 添加扫描的专项缺陷

现有工具表有 `add_scan`，但本轮确认它不能被当作已经可用的完整导入链路。

1. **创建前发生缩放类型错误。** `validateAddScan` 返回数字 scale；执行器却传入 `[scale, scale, scale]`。`ScanNode` 要求数字，生成预览时抛出 `Invalid input: expected number, received array`。隔离调用真实校验函数和 `buildMutationCommands` 已复现，无网络请求、无用户场景写入。
2. **本地资源 URL 不被该 AI 校验器接受。** 手动导入得到 `asset://...`，`validateAddScan` 只接受 HTTP/HTTPS，直接返回 invalid。它和 core 的资产地址规则尚未对齐。
3. **不透明度范围不一致。** 工具说明和校验默认是 `0–1`、默认 `0.5`；scan schema/renderer 使用 `0–100` 并除以 100。因此只修复 scale 后直接传 `0.5`，会得到 0.5% 而非预期 50% 不透明度。此项由 schema 实值与渲染公式核对，未做界面视觉验收。

这些问题影响 AI 工具路径，不能据此断言手动上传也失败；手动路径使用数字 scale 和 100% opacity，没有经过这段执行器。

依据：[AI 扫描校验](../../packages/editor/src/components/ai/mutation/validate-structure.ts:1255)、[创建扫描命令](../../packages/editor/src/components/ai/preview/confirm-operations.ts:853)、[节点 schema](../../packages/core/src/schema/nodes/scan.ts:15)。

## 5. 与目标入库功能相比还差什么

| 目标 | 可以复用 | 必须补充 |
| --- | --- | --- |
| 添加文件 | 文件选择、大小提示、现有加载器 | 多文件与依赖处理、格式/资源检查、真实加载成功状态 |
| 自动测量与校正 | 变换与模型显示基础 | 基准宽高深、单位、正面/锚点、落地或挂载校正 |
| 分类和命名 | 文件名初始命名、原生重命名控件 | 受控分类树、中英文名称/别名、用途、字段来源 |
| AI 帮助入库 | 当前内置 AI 配置及工具基础 | 将草稿和测量结果交给 AI；结构化建议回填；视觉识别另补图片输入 |
| 成为可复用模型 | GLB 加载能力 | 独立资产 ID/版本、缩略图、统一目录、发布与缓存同步 |
| 多项目与跨环境使用 | 场景中可保存 URL 引用 | 宿主文件持久化、完整资源打包/恢复、引用保护 |
| 材质和款式切换 | 原始材质显示 | 可换部位识别/适配、材质方案、产品款式关系、原位替换事务 |
| 正确摆放 | 现有普通 item 的摆放框架 | 从入库资产提供尺寸、安装类型、锚点和承载/净空规则；scan 节点本身不具备这些完整语义 |

## 6. 建议的改造方式

同一套文件接收和解析服务支持两个用途：“作为扫描/参考”和“加入模型库”。前者保留当前工作方式；后者进入校验、测量、AI 补资料、分类确认、发布流程。模型库新增入口与扫描入口共用底层，避免出现两套不一致的资源存储。

对已经导入的 scan 增加“保存为模型资产”操作：

1. 找回原始文件；如果文件已经缺失，明确提示补回，不能发布悬空引用。
2. 检查它是独立物件还是整屋/整场景；整屋不能直接分类为一张桌子，也不能默认自动拆分。
3. 读取几何、材质与依赖，校正基准尺寸和安装方向。场景中为对齐参考而做的缩放不应未经确认写成产品真实尺寸。
4. 用现有 AI 建议名称、分类、标签和待确认项，用户集中确认。
5. 发布独立资产记录，让模型库和 AI 共用。默认保留原扫描参考，用户明确选择时再以普通物件放置或替换。

实施优先级：先修复 `add_scan` 的参数契约并补专项回归；再提取共享导入/检查基础，完成一个独立 GLB 从扫描保存为模型、被 AI 调用、保存重开的试点；随后扩展批量和材质/换款。

## 7. 本轮验证记录

- `asset-storage.test.ts` 与 `scan.test.ts`：13 项通过、0 失败；覆盖模拟 IndexedDB 的保存读取与 scan schema。
- `local-guide-image.test.ts`：1 项通过、0 失败；使用模拟 saveAsset 验证创建 scan 并归属楼层。
- 独立进程调用真实 `validateAddScan → buildMutationCommands`：HTTPS 输入校验通过，构建因 scale 数组失败；`asset://` 输入在 AI 校验阶段被拒绝。
- 不透明度核对：schema 接受 `0.5`，renderer 归一化得到 `0.005`。

14 项既有测试通过不代表扫描功能没有问题：它们没有覆盖这条 AI 执行器路径。前轮 43 项 AI 通用测试也未覆盖 `add_scan` 创建，不能用其通过结论替代本轮扫描专项结果。
