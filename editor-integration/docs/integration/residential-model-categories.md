2026-09-20 已应用到本机模型库。按物件用途建立主分类，地区、年代、建筑风格和季节作为可交叉检索的标签；不把“美国”当作一种统一外观。

## 归属边界

- 一件资产只有一个主分类。空间用途用标签表达，例如餐桌归室内家具，标签可包括餐厅、厨房、早餐区。
- 厨房专用电器归厨房餐饮，洗衣设备归卫浴洗衣；家电设备主要收录跨空间设备。
- 盆栽陈设归室内装饰，景观树木归自然环境；户外家具及人工庭院设施归庭院户外。
- 灯具统一归灯具照明，用室内、庭院、门廊、街道等标签区别用途。
- 参数化建造工具（墙、道路、门窗、地形等）仍是建造工具，不计入模型数量；导入的同类 GLB 资产才属于模型库。
- 稳定 ID 与显示名称分离。重命名和调整分类不改变模型 ID、几何尺寸或既有场景中的资产快照。

## UI 与 AI

- 一级分类以紧凑图标按钮横向排列并换行；子分类每次只展示下一层，点击原地进入，最多三级路径始终保持一行。
- 路径名称返回上级，路径旁的按钮通过 Radix Popover + cmdk 搜索切换同级；“查找分类”可跨层级跳转。下级超过两个时提供可搜索的“更多”。
- 完整树放在独立的“管理分类”窗口；日常浏览不再展开树。Radix Dialog 统一管理分类、宽版浏览和模型编辑的焦点及弹窗层级。
- 搜索默认跨整个模型库（当前状态），可勾选“仅当前分类”。卡片保留完整分类路径提示。
- “展开模型库”提供宽版缩略图网格；收起保留筛选条件，宽版和侧栏分别保存本次打开期间的滚动位置。选择模型后关闭宽窗口，进入实际场景放置。
- 每级数量累计自身及全部后代的模型，按已入库、待入库、回收站分别计算。
- 分类管理继续复用 React Arborist，支持树形编辑；跨大类调整时进入“管理分类”。
- 模型目录为 AI 提供当前 category ID、各级名称和完整路径；分类更改由现有模型库刷新机制同步。
- 分类路径明确并不保证所有自然语言请求都能识别。新增资产仍需要中英文别名、用途、安装方式、尺寸以及用户确认。
- 地区、年代、风格、季节、材质等是后续元数据完善方向；本轮没有给全部资产推断或批量填充这些标签。
