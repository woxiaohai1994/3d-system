# Add Camera Rigs completion audit

Objective: integrate the original core algorithms and interaction in this system with Blender-equivalent behavior, and delete the previous gaze implementation. This audit is stricter than the earlier passing integration summary. The goal remains active; a passing matrix fixture set is not proof of complete product equivalence.

## Verified in current source

- The pinned upstream archive and all 17 vendored files were compared byte-for-byte. Source widgets, bones, locks, hierarchy, constraints and driver expressions come from the upstream code, not a hand-drawn replacement.
- Dolly has 4, Crane 6, and 2D 8 exposed source controls. The browser runtime requires no Blender process or service.
- `scripts/blender/export-camera-rigs.py` produces 143 differential cases. Native camera/projection matrices and each widget's shape/pose/edit matrices match original Blender output within the fixture tolerance. Coverage includes landscape/portrait, perspective/orthographic, individual transforms, partial tracking, combined nonuniform Root scale and rotation, mirrored Root transforms, independently inherited crane translation, Camera scale, Shift to Pivot, target binding, Dolly Zoom expressions, lens breathing and 2D Aim DOF influence.
- Nonuniform-scale constraint blending uses polar matrix interpolation, matching Blender `interp_m4_m4m4`; Copy Rotation uses Blender's symmetric Y-axis orthogonalization. Implementation: `packages/viewer/src/lib/rig-matrix.ts`. Primary references: [Blender matrix routines](https://github.com/blender/blender/blob/main/source/blender/blenlib/intern/math_matrix_c.cc), [constraint evaluation](https://github.com/blender/blender/blob/main/source/blender/blenkernel/intern/constraint.cc).
- Bone inheritance now keeps separate location and rotation/scale matrices, following [Blender armature evaluation](https://github.com/blender/blender/blob/main/source/blender/blenkernel/intern/armature.cc). Copy Location and Damped Track retain shear; signed-scale matrix setters use Blender Euler extraction.
- `rig-projection.test.ts` compares 143 original Blender projected-point cases through the system output camera, main-view crop, and saved/detached camera. `viewCorrection` preserves residual shear instead of losing it during Euler conversion. Timeline capture and detached-camera sampling also preserve the correction.
- `export-camera-rig-operators.py` records 18 original operator cases, including transformed Dolly/Crane setups. Set/remove Dolly Zoom and Swap Lens match upstream directly. Actual testing confirms Swap Lens writes the matrix successfully; the earlier suspected defect was not reproduced. The focus callback does reproduce `StopIteration` because it searches the wrong driver; the fixture records raw upstream behavior separately from the intended Aim/DOF target. Vendored source remains unchanged.
- The 2D `MCH-DOF_Parent` Copy Location influence is persisted as `dofTracking`, exposed as Aim DOF, sampled with camera keys, and compared against Blender at 0, .25, .5 and 1.
- `camera-gaze`, editor gaze navigation/handle, and the earlier independently written rig solver were removed. The additional legacy `scene-camera-target` solver and its `movementMode` / top-level `targetId` schema, renderer and gizmo branches are now removed too. Rig Aim owns camera targeting.
- Browser regression exercises source controls, every XYZ axis of pointer translation/rotation/scaling under nonuniform parent transforms, axis locks, Esc, single-step undo, keyframes, interpolation, Dolly Zoom, focus-on-Aim, 2D controls, Aim DOF persistence, preview, MP4 export and reload. See the latest `.integration-audit/camera-rigs/result.json`; fixture testing uses a separate browser context rather than overwriting the user's scene.

- The right-side viewport rig panel has compact XYZ fields and visible disabled axes. Framing reserves space for the panel; screenshots and browser geometry checks at 1680×1100 and 1280×900 verify all 2D labels remain outside it.
- The current combined camera regression set has 355 passing tests, including 76,995 assertions; core/viewer/nodes build and editor type checks pass. Choosing a focus target no longer forces DOF on; the existing camera DOF enable remains independent.

- `scripts/camera-rig-lens-browser.mjs` passes independent unkeyed/keyed projection, clip, Shift, sensor, focus, breathing, moving-subject and reload checks on localhost:3002. `scripts/camera-rig-display-browser.mjs` passes original guide/limit controls, horizontal/vertical frame geometry, visibility and metadata persistence in separate browser contexts. Screenshots are in `.integration-audit/camera-rigs-lens/` and `.integration-audit/camera-rigs-display/`.

- External scene parents now participate in WORLD-space constraints and driver variables; POSE-space constraints remain local. Source extraction records each constraint space. Focus depth uses the full world transform. Main camera view and photographic output share the normalized optical-axis adapter, preserving parent shear/reflections. `rig-parent.test.ts` verifies 24 original Blender cases, every widget matrix, optics and output/main-view projected points. An additional integration test samples animated parents at out-of-order times without mutating their displayed transforms. Parent-aware creation, manual navigation and source operators still need end-to-end interaction coverage.

A new real-pointer photographic workflow (`scripts/camera-rig-photo-browser.mjs`) exposed and fixed rig photos incorrectly using the 360p timeline preview resolution. Source-rig photos now honor 720p/1080p. The reference uses [Cycles camera.cpp](https://github.com/blender/blender/blob/main/intern/cycles/blender/camera.cpp): perspective aperture radius is lens-in-metres / (2 × f-stop); orthographic radius is 1 / (2 × f-stop), with convergence at the focus plane. This is a Cycles reference; [EEVEE's orthographic DOF convention differs](https://github.com/blender/blender/blob/main/source/blender/draw/engines/eevee/eevee_depth_of_field.cc).
- This audit **contradicts full current DOF equivalence**: `cameraDepthOfField` plus Three's stock DepthOfFieldNode uses an artistic smoothstep/falloff and a fixed 12-pixel maximum sampling radius. At 320×180, 120 mm, f/1.4 and 4 m focus, native perspective radii are 34.286 px at 1 m and 7.619 px at 12 m. Measured native edge widths are 47.027 px and 10.511 px; the current shader's nominal sampling radius saturates at 12 px for both. Orthographic cameras also need their own aperture/projection model. The native renders validate the new reference, not the application renderer.
